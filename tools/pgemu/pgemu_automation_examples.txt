pgemu tips: what the README does not state. Each one measured 2026-09-27.

- macOS sandbox (an agent's shell): Unicorn is killed at start, exit 132. Run pgemu outside the sandbox.
- unicorn is not installed on this Mac. Each task installs it into its own venv, `_Project_Improvements/_scratch/<task>/venv`, and loses it when that folder is cleaned.
- Inside the sandbox pip fails the certificate check, OSStatus -26276, with or without pypi.org declared (2026-10-01). Install outside it: `<venv>/bin/pip install --no-cache-dir unicorn`.
- Run pgemu with that venv's python, `<venv>/bin/python3 tools/pgemu/pgemu.py ...`, one direct command per call, outside the sandbox.
- The auto mode gate rules on each session separately: it allowed both calls in the MR 1929 and PRINT_Y_X sessions and refused the install twice in the package 4 session (2026-10-01).
  A Bash allow rule for the venv's pip and python in `.claude/settings.local.json` let both through there, the same day:
  `Bash(<venv>/bin/pip install *)` and `Bash(<venv>/bin/python3 /Users/jacomostert/c43/tools/pgemu/pgemu.py *)`, with <venv> written out in full.
- A DM42 .pgm file is 20 bytes longer than its prog_info count: 714348 on disk is 714328 on the prog_info line. Compare the prog_info figures.
- On the C47, f then EXIT is OFF: the run stops at STAT_PGM_END before a later snap, so that case has frames and no capture.
- An A/B is two builds of one tree: check the byte count on the prog_info line differs before comparing (1128640 with fix 51b3e9c8e, 1128592 without).
- A tree taken with git archive has no .git: its pgm_ver, and so the "built from" line, names the commit of the repository around it, not the one built.
- Refresh faults show only on the route that has them: READP typed by name without 51b3e9c8e leaves 960 bytes of status bar, READP from the I/O menu none.
- A STACK_WATERMARK image paints its own stack: --stack-watermark then reports that span, 8136 on a DM42 build painting 8088, not a depth.
- DM42 without its DMCP image: malloc is the host's, so a stack overrun into heap_4 does not crash. PLOT over INT completes where the DM42 crashed.
- DM42 engine nesting cap is 2: PLOT over INT over INT gives "Operation aborted". That is the firmware, not pgemu.
- --choose takes the calculator's backslash: 'PROGRAMS\NAME.p47', the file placed in tools/pgemu/fs/PROGRAMS/.
